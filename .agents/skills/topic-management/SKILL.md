# 研究主題管理

## 輸入與參考

輸入為主題名稱／ID、說明、關鍵字及要求的操作；父主題與狀態可選。先讀 [共用規範](../../../docs/conventions.md) 的執行邊界、根目錄、ID、Front Matter、人工保護及變更審核；新增時讀 [主題模板](../../../templates/topic.md)。以本 Skill 向上三層定位專案根。

僅使用宿主既有檔案工具，不執行自訂程式或腳本。缺工具按 [環境說明](../../../docs/environment.md) 降級。

## 前置檢查與流程

1. 搜尋現有主題的 ID、名稱、關鍵字及狀態；多個同名候選先列 ID 與連結，不自行挑選或新增近似副本。
2. 新增：依規範產生未用 T ID，確認名稱與說明足以辨識，檢查 parent_id 存在且無循環。使用模板建立 `topics/T-ID.md`（檔名即實際 T ID），summary_path 指向自身；不生成第二份摘要或把範例當研究內容。
3. 修改：先讀完整舊文件。明確單一 metadata 操作可執行，只更新要求欄位、updated 及必要的正文名稱；不改 ID、檔名、人工區或既有生成區。
4. 父子調整：沿 parent_id 回溯，禁止自指與循環；不隱含更動筆記歸屬，也不自動改子主題狀態。需要更動既有筆記的 topic_ids 時，讀 [筆記流程](../note-capture/SKILL.md) 並先展示草案。
5. 封存／暫停：保留文件與所有關聯；說明彙總與圖譜尚未重新產生。批次變更先審核；不要藉改題自動刪除或搬移歷史資料。
6. 寫前再讀目標並查 ID，寫後讀回，核對 metadata、summary_path、parent_id 與兩組標記。若新增失敗先查檔案是否部分建立，再續接。

## 輸出與審核

提供主題 ID、檔案連結、狀態、父主題及實際變更，列出受影響而未更新的摘要／圖譜。未明確要求彙總時，生成區保持模板的「尚未彙總」。

同名歧義、資料版本未知、循環、既有 ID／路徑衝突時停止相關寫入並列具體候選。修改人工區、批次改寫及連帶筆記變更須先展示舊／新內容與來源，再取得確認；已有同一具體草案授權不重問。

## 範例

- 「建立可靠性評估主題，底下新增工具失敗子主題」：建立兩份主題文件，子主題 parent_id 指向父主題。
- 「將 T-20261110-001 改名為 Agent 任務可靠性」：保留 ID、路徑與人工內容。
- 「封存這個主題」：目標唯一才更新狀態，不連帶封存筆記或子主題。
- 「更新主題摘要」：改用 topic-synthesis，不以主題管理重建摘要。
