# 研究檢索與導覽

## 輸入與參考

輸入為自然語言查詢、篩選條件或研究問題。先讀 [共用規範](../../../docs/conventions.md) 的根目錄、檢索去重、關聯契約及執行邊界。由 Skill 向上三層定位專案根。按需要讀 [環境能力](../../../docs/environment.md)。

## 工作流程

1. 將請求轉為 ID、主題、類型、標籤及文字條件；多個明確篩選預設同時滿足。主題名稱多義先列候選。未要求包含子主題時只查直接歸屬。
2. 在正式 topics／notes／references 中使用宿主既有搜尋工具；正式操作排除 docs、templates、.agents、backups 與 test_fixture，明確隔離驗收依共用規範切換資料根。沒有自訂索引或向量搜尋，不寫程式做排序／掃描。
3. 讀取每個命中檔案與證據上下文。區分關鍵字命中與真正支持回答的證據；主題摘要／圖譜只供導覽，結論回到原始筆記。根目錄沒有正式資料時直接回報，不拿驗收例子湊結果。
4. 沒有精確結果時可用同義詞再搜尋，回覆說明擴展詞與條件。掃描不完整或工具不足時記實際覆蓋，不能聲稱找出所有。
5. 回傳 ID、檔案／段落連結、類型、主題與命中理由。問答每項關鍵論點附證據，分開來源報告、使用者意見及 Agent 推論；無證據明說，衝突並列。
6. 用到語意關聯時重讀其端點與證據；失效者本次標需重審，不沿用舊 confirmed。唯讀流程只提出台帳修改建議，不修改狀態。
7. 只有使用者要求公開補查時才外查；不將私人內容或內部名稱送出。補查發現的新引用另列候選，不在此 Skill 寫入既有筆記。要保存／補全時按 [筆記流程](../note-capture/SKILL.md) 先審核。

## 輸出與失敗處理

簡短結果表列 ID、可定位連結與理由，接有證據的回答、範圍及限制。沒有命中就明說條件；網路、PDF、檔案閱讀能力不足時請提供內容或交付已讀部分，不安裝工具／執行腳本。

本 Skill 預設不產生檔案變更、不重建彙總／圖譜、不補 DOI。使用者另要求保存時，由宿主載入對應寫入流程；搜尋本身不是變更授權。

## 範例

- 「找出可靠性主題內所有提到 LLM-as-a-Judge 的 Paper」：依主題、類型、詞彙交集搜尋；揭露覆蓋。
- 「N-20261110-001 的結果有什麼限制？」：讀證據與閱讀範圍後回答，不依摘要猜全文。
- 「哪些證據支持這個主張？」：列關聯及原始 E 段落，待確認邊保持待確認。
- 「幫我更新 DOI」：先轉筆記補全草案與審核，不以唯讀搜尋偷偷改檔。
