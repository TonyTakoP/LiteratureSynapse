# 關聯與知識圖譜

## 輸入與參考

輸入為主題／中心節點 ID、關聯建議或接受／拒絕操作、可選一階／二階及包含子主題範圍。先讀 [共用規範](../../../docs/conventions.md) 的執行邊界、ID、實體台帳、關聯契約、Mermaid 與審核；按需要讀 [實體](../../../templates/entities.md)、[關聯](../../../templates/relations.md)、[圖譜](../../../templates/graph.md) 模板。專案根由 Skill 向上三層定位。

本論文文獻整理依[逐篇累積約定](../../../docs/conventions.md#本論文逐篇累積約定)，可新增問題／主張及 proposed 關聯，再由宿主 Agent 更新摘要後依台帳重建主題圖。仍須查重並回到 N／E 證據；不把 Survey 引用名單建成假定已讀的文獻節點。單純繪圖與純查詢不因此新增台帳內容。

## 工作流程

1. 分清「記錄關聯」與「從既有資料繪圖」。純繪圖不新增實體／關聯；範圍不明才釐清。讀取正式主題／筆記及相關台帳，不將模板或驗收樣本當正式資料；明確隔離驗收依共用規範切換資料根。
2. 要建立問題／主張時，查已有 Q／C 是否重複，連回原始筆記證據，標示來源／使用者／Agent 歸屬。從純想法提取的主張仍是待驗證，不能升為事實。必要時先按筆記流程保存已授權的原始靈感。
3. 明確要求記錄關聯或符合本論文逐篇約定時，檢查端點、方向、受控類型、三元組去重及證據位置，產生 R ID。Agent 建議一律 proposed；使用者明確提供的關聯若授權保存，可記 confirmed 並保留確認內容。逐篇約定本身不代表確認任何語意關聯。belongs_to 只由 topic_ids 衍生。
4. 既有實體／關聯修改、引用補全、proposed 轉 confirmed／rejected，先展示逐 ID 草案、依據與影響；獲確認且保留回復能力後才寫。若使用者已接受同一具體草案不重問。
5. 每次用到關聯都重讀端點與證據。變更或失效需重審時，列 needs_review 修改草案；尚未獲准則不改原列，但本次圖表以需重審虛線／警示呈現，不能沿用 confirmed。端點不存在／類型錯誤的邊不畫並列錯誤。
6. 依主題或一／二階範圍挑選節點，按規範產生 flowchart LR、類型標籤與含 R／B 識別的邊。每圖不超過 30 節點、50 邊；超量依 ID 穩定拆圖、保留中心並列省略清單。不推導傳遞關係。
7. 節點來源表連到 N／T 文件或 Q／C 段落；邊證據表逐條連回 N／E、列狀態與適用條件。明記閱讀範圍、實際生成時間與未讀／失效資料。
8. 新圖按模板建立；既有圖僅替換合法 GENERATED 區與生成 metadata。先讀舊檔再寫後核對，不覆蓋人工註記。沒有標記時先展示遷移草案。

## 輸出與能力限制

回覆實際台帳／圖譜連結、待確認 R ID、已讀範圍、拆圖／省略及渲染狀態。沒有原生 Mermaid 預覽時標「未經渲染驗證」，仍交付 Markdown 原始碼。不執行自訂程式、Mermaid CLI、套件或其他 Skill 的渲染腳本。

SVG 非預設，只有原生免程式碼匯出已驗證且另獲授權時選用。沒有來源或無法重驗時保留疑義，不捏造關聯。若空範圍，交付無節點原因，不把空 flowchart 稱為已成功渲染。

## 範例

- 「這篇論文可能支持 C-20261110-001，記下來」：有證據的 proposed，顯示理由與確認途徑。
- 「接受剛才 R-20261110-001 的草案」：確認所指草案後更新該列及審核歷史，不影響其他列。
- 「繪製這個主題」：僅讀既有來源與台帳，產生 Mermaid 與逐邊出處。
- 「產生 SVG」：先檢查原生能力；沒有就說明並提供 Mermaid，不安裝轉換工具。
