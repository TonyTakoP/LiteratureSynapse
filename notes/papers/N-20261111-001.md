## 來源內容／證據

以下均為來源轉述；未加引號的內容不是逐字引文。Survey 對其他研究的描述保留為二手證據。

### E001

- 定位：摘要、§1.3，HTML 錨點 Abs1、Sec4。
- 轉述：本文以五個研究問題整理 LLM 事實查核：RQ1 評估指標；RQ2 幻覺對可靠性的影響；RQ3 訓練與評估資料集；RQ4 提示策略、微調與領域適應；RQ5 RAG 的整合與限制。
- 適用條件：本文同時涵蓋「用 LLM 查核外部主張」與「查核 LLM 生成內容」，引用時須辨明任務。

### E002

- 定位：§3.1、§3.3，錨點 Sec9、Sec11。
- 轉述：作者搜尋 Web of Science、Scopus、arXiv、OpenReview；方法章記載的檢索出版區間為 2021-01-01 至 2025-09-15。作者報告初始取得 14,685 筆紀錄，經去重及分階段篩選後納入 64 篇，納入文獻的出版時間為 2022 年 9 月至 2025 年 8 月。
- 轉述：§3.3 將範圍限定於使用 LLM 驗證外部主張或事實內容的研究，排除只分析幻覺或內部事實一致性的研究。
- 不確定性：摘要概括為 2020–2025，與方法章的起點不同；本筆記保留差異。上述數量為作者報告，未重跑檢索，也未逐筆核對圖 2 的篩選流程。

### E003

- 定位：§4.1.1，錨點 Sec14。
- 轉述：Accuracy、Precision、Recall、F1 與 Macro-F1 常用於主張真假、支持／反駁／無法判定，或回答錯誤偵測等分類任務。
- 限制：整體 Accuracy 可能受類別不平衡影響；把複雜回答壓成單一正誤標籤，可能掩蓋部分錯誤、推理與解釋品質。

### E004

- 定位：§4.1.2，錨點 Sec15。
- 轉述：BLEU、ROUGE 等衡量字詞重疊，BERTScore、BLEURT 等衡量語意相似；高相似度仍可能伴隨事實錯誤，不能直接用來代表事實正確性。
- 適用條件：這些工具可作輔助文字品質訊號，但其分數不能直接解讀成回答正確率。

### E005

- 定位：§4.1.3，錨點 Sec16。
- 轉述：以證據支持為核心的評估，將回答中的句子或主張對照來源，判斷支持、反駁或無法驗證。本文列舉 LLM-AGGREFACT、ReaLMistake、LEAF fact-check score、NLI 等不同工具與任務。
- 轉述：LEAF 的介紹採分解回答並驗證句子的方式，彙整事實支持程度；LLM-AGGREFACT 為整合多個資料集的 benchmark。
- 限制：評估依賴證據品質及判定器能力。本節混合指標、benchmark 與驗證方法；使用前仍需回到原論文確認定義、評分單位及分母。

### E006

- 定位：§4.1.4、§4.1.6，錨點 Sec17、Sec19。
- 轉述：LLM 可用來分解主張、挑選證據、分類錯誤及評分，降低人工負擔；評分仍可能受提示措辭、偏誤與誤判影響，需要與人工判斷核對。
- 轉述：Zero-shot、Few-shot、CoT、ReAct 等是提示或推理策略，本身不是評估指標。
- 適用條件：LLM 判定結果不能未經驗證就當成標準答案。

### E007

- 定位：§4.1.5，錨點 Sec18。
- 轉述：人工評估用於事實正確性、解釋清晰度、涵蓋度及整體品質；人工標註也常作為 benchmark 的參考答案。
- 限制：人工評估耗時、有成本，並受評分者及準則差異影響。

### E008

- 定位：§4.2.1，錨點 Sec21；圖 7、圖 8 的文字說明。
- 轉述：Intrinsic hallucination 指輸出與來源矛盾；extrinsic hallucination 指加入來源未支持、無法由所給證據驗證的資訊。本文另區分相對輸入脈絡的 faithfulness，與相對外部世界知識的 factuality。
- 適用條件：這些分類的參照對象不同。來源未支持與外部世界中已證偽，不能自動視為相同判定。

### E009

- 定位：§4.3，錨點 Sec24。
- 轉述：本文列舉 FEVER、FEVEROUS、HOVER 等主張驗證資料；SciFact、PubMedQA 等領域資料；HaluEval、ReaLMistake、TruthfulQA 等評估資源，也討論多語及多模態資料。
- 轉述：資料的任務、領域、標註品質、語言與來源差異會影響模型表現及泛化；本文也提醒資料範圍狹窄與偏誤問題。
- 限制：上述名單依 Survey 整理，不表示各資料集的原始任務完全相同；未核讀各資料集原論文或表 5、表 6 完整內容。

### E010

- 定位：§4.4 的已讀重點段落，尤其 §4.4.1–4.4.5，錨點 Sec26–Sec30。
- 轉述：單靠 Zero-shot、Few-shot 或 CoT 不保證改善事實查核；結合外部檢索、主張分解及逐步驗證是本文討論的重要方向。領域微調的小模型在特定任務上可能優於通用大模型。
- 限制：效果取決於任務、資料與設計，不能把某個 benchmark 的優勢外推到所有企業情境；本筆記不引用尚未回原論文核對的提升百分比。

### E011

- 定位：§4.5、§4.5.1，錨點 Sec31、Sec32。
- 轉述：RAG 在推論時引入外部來源，支援查核與可追溯回答；本文整理從單次檢索流程走向反覆檢索、驗證與規劃的系統。
- 限制：相關證據可能不存在或難以取得；檢索會帶入雜訊與無關文件，並受脈絡長度、資訊時效、來源衝突及多步推理影響。具備 RAG 不代表答案必然正確。

### E012

- 定位：§5–8，錨點 Sec33–Sec36；Data availability。
- 轉述：作者主張評估應同時關注事實性、證據來源、邏輯一致性、解釋品質及對抗擾動下的表現，並重視真實、多語與領域資料。
- 轉述：結論承認研究發展快速，新的預印本、封閉模型進展與實務做法可能未完整涵蓋；Data availability 聲明本研究未產生或分析新資料集。
- 適用條件：這是文獻綜述提出的研究方向，不是已驗證適用於企業 Agent 的完整量表。

### E013

- 定位：附件 References，ref-CR39、ref-CR52、ref-CR55、ref-CR82、ref-CR83、ref-CR96、ref-CR98、ref-CR106。

## Agent 摘要／推論

### 研究問題

本文以五個 RQ 組織事實查核研究，適合用來建立回答正確性文獻回顧的初步分類表。參見 [E001](#e001)。

**Agent 建議／待確認：** 第一階段可聚焦「既有研究如何定義與衡量 LLM／Agent 回答的正確性，以及這些評估方式如何用於以企業文件為依據的問答」。此問題是對使用者研究方向的延伸，尚不是已確認的研究設計。

### 方法

本文採資料庫檢索、去重、標題摘要篩選、全文篩選及依 RQ 分類的文獻綜述方式；納入規模與期間見 [E002](#e002)。引用研究方法時應保留摘要與方法章期間不一致的註記。

### 實驗設計

本文彙整既有研究，不提供一套本筆記可直接重現的企業 Agent 統一實驗。各研究的模型、任務、資料集及指標條件不同，本筆記不跨研究直接排名，也不將 Survey 報告的改善幅度當作本題的預期效果。依據 [E002](#e002)、[E010](#e010)、[E012](#e012)。

### 主要發現

| 評估面向 | 來源介紹的方式 | 對本題的整理重點 |
| --- | --- | --- |
| 分類結果 | Accuracy、Precision、Recall、Macro-F1 | 先確認衡量的是查核器判定，還是 Agent 回答；標籤不平衡時不能只看 Accuracy。[E003](#e003) |
| 文字相似 | BLEU、ROUGE、BERTScore 等 | 可輔助比較表達，不能直接替代事實正確性。[E004](#e004) |
| 證據支持 | 句子／主張級驗證、NLI、事實支持程度 | 區分回答與證據的對應關係，釐清評分單位與無法判定的處理。[E005](#e005)、[E008](#e008) |
| 自動評審 | LLM 評分及驗證 | 需以人工資料核對評分可信度。[E006](#e006) |
| 人工評估 | 標註與品質量尺 | 保留事實、解釋品質與整體品質的不同準則。[E007](#e007) |

RAG、提示策略與領域適應是改善系統的方法；評估指標是判定改善與否的工具。筆記與後續文獻表應分欄記錄，避免混用。[E006](#e006)、[E010](#e010)、[E011](#e011)

### 限制與閱讀時需留意的問題

- **來源範圍限制：** 本文主要處理事實查核及生成內容，企業操作流程與任務完成率尚需其他文獻支持。[E001](#e001)、[E002](#e002)
- **評估對象容易混淆：** 查核器的分類正確率、回答的證據支持比例、檢索命中率各自評估不同環節；不能互換名稱或分母。[E003](#e003)、[E005](#e005)、[E011](#e011)
- **二手分類需回查：** 本文在部分段落並列指標、benchmark、資料集與框架；後續建立正式文獻表時，應以原論文確認類型及定義。[E005](#e005)、[E009](#e009)
- **參數名稱需核對：** §4.1.3 對 IMR 的名稱與「低分回答比例」的文字定義值得回查 FACT-AUDIT 原文；本筆記暫不採用其公式。[E005](#e005)
- **證據與泛化限制：** 不同語言、領域及來源品質可能改變表現；小模型、CoT 或 RAG 的特定結果不代表普遍優劣。[E009](#e009)–[E012](#e012)

### 與論文題目的連結：Agent 建議／尚待確認

以下是依使用者題目與上述來源提出的操作化建議，不是 Survey 的既定公式，也不是教授已同意的方案。

| 暫定評估層次 | 可能的觀察單位 | 待決定事項 |
| --- | --- | --- |
| 回答正確性 | 一個問題的完整回答 | 全對、部分正確及錯誤如何評分？拒答與無法回答如何計入？ |
| 證據支持程度 | 回答中的可查核主張 | 分別記錄支持、矛盾、證據不足；另外檢查必要資訊是否遺漏。 |
| 任務完成率 | 一次 Agent 操作及最終環境狀態 | 以達成使用者目標的可觀察結果判定；回答正確不等於操作成功。 |

可先從文件問答場景設計小規模評估，再決定是否延伸工具操作；目前企業場景尚未選定。任何主張級比例都須先定義分母及無可查核主張的處理，不把「沒證據」直接當成「已證偽」，也避免只靠少回答取得高分。推論依據：[E003](#e003)–[E009](#e009)、[E011](#e011)。

### 後續追讀順序：Agent 建議

以下候選皆取自附件引用，尚未閱讀原論文；順序依本題第一階段需求安排。[E013](#e013)

| 優先度 | 候選原始研究 | 追讀目的 |
| --- | --- | --- |
| 1 | MiniCheck: efficient fact-checking of LLMs on grounding documents（2024） | 了解文件支持判定、驗證器及 LLM-AGGREFACT 的實際評估方式。 |
| 1 | Evaluating LLMs at detecting errors in LLM responses（2024） | 了解評審模型偵測錯誤的可靠性與 ReaLMistake 任務。 |
| 1 | HaluEval（2023）；TruthfulQA（2022） | 分別核對幻覺偵測與真實性問答任務，避免當成同一種回答正確率。 |
| 2 | Provenance（2024）；LEAF（2024） | 比較 RAG 輸出驗證及查核回饋流程。 |
| 2 | AVERITEC（2023）；OpenFactCheck（2025） | 了解真實主張、證據取得及可客製查核評估。 |

逐篇文獻表建議記錄：評估對象、任務與領域、輸入／輸出、標準答案與證據來源、評分單位、指標及分母、評審方式、人工一致性、模型與版本、資料集與語言、限制、企業情境適用條件及原文定位。

## 待確認事項

- 與教授確認「回答可靠性」第一階段是否限於事實正確與文件支持，或包含完整性、重複回答穩定性及不確定性表達。
- 選定企業問答場景、使用語言、文件版本與權威來源，以及需要工具執行的任務是否留到第二階段。
- 明定答案級與主張級判定準則，以及部分正確、拒答、證據不足和來源衝突的處理。
- 回到候選原始論文核對評分定義、資料集任務、實驗條件與版本；本文的二手量化數據暫不作實驗設計依據。
