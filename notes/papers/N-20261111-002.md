## 來源內容／證據

以下為明確轉述；架構觀察與作者建議分開記錄。來源版本固定為 v1，描述系統功能時不視為查閱當日的最新產品規格。

### E001

- 定位：[§2.1–2.3、表 1](https://arxiv.org/html/2609.00006v1#S2)。
- 轉述：作者將 Agent 分為模型與 harness 執行層，後者涵蓋七個面向：迴圈、模型整合、工具、記憶／脈絡、安全／權限、協作及擴充。
- 適用條件：這是 coding-agent 架構分類；不是已量化驗證的回答可靠性量表。

### E002

- 定位：[§4.1–4.2、表 3](https://arxiv.org/html/2609.00006v1#S4)。
- 轉述：本文比較十一個系統的原始碼架構，另以 Omnigent 作 meta-harness 對照；依固定版本分析，並保留部分系統的早期快照作縱向比較。
- 限制：選樣包含非純 coding-agent 對照；個別系統採非官方流傳快照，不宜把所有樣本的可重現性視為相同。

### E003

- 定位：[§5](https://arxiv.org/html/2609.00006v1#S5)、[§15.5–15.6](https://arxiv.org/html/2609.00006v1#S15)。
- 轉述：研究是原始碼分析，沒有將所有系統放在共同任務、相同模型與設定下實測。作者承認架構比較有判斷成分，引用的 benchmark 數據來自不同條件的自報結果；複雜度與成功率的前緣只是待測假說。
- 適用條件：本文不能直接證明某架構提高企業任務完成率，亦不能據自報分數作公平排名。

### E004

- 定位：[§16.1–16.4](https://arxiv.org/html/2609.00006v1#S16)。
- 轉述：作者建議從簡單線性迴圈及小工具集合開始，依實際失敗再加功能；編輯工具的契約須配合模型能力。
- 限制：原建議以 coding 任務為背景；不表示企業 Agent 應預設取得通用 shell。

### E005

- 定位：[§16.5](https://arxiv.org/html/2609.00006v1#S16.SS5)。
- 轉述：作者建議分層載入 Markdown 脈絡、達門檻時壓縮對話並保留近期資訊；對程式碼檢索優先考慮檔案、字詞及語法結構。
- 限制：脈絡摘要仍可能遺漏；對 code retrieval 的建議不能直接外推成企業文件問答不需要 RAG。

### E006

- 定位：[§16.6–16.8](https://arxiv.org/html/2609.00006v1#S16.SS6)。
- 轉述：作者區分開發工具與企業／共用環境，後者需考慮隔離、權限政策與稽核；協作先從單 Agent 起步，待有具體需求再擴充。
- 適用條件：權限及協作是架構取捨，不等同回答正確性已獲驗證。

### E007

- 定位：[§16.9、建議 15–18](https://arxiv.org/html/2609.00006v1#S16.SS9)、[§15.6](https://arxiv.org/html/2609.00006v1#S15.SS6)。
- 轉述：作者從所查樣本提出避免過度框架化、向量程式碼檢索與工具膨脹的建議；也承認依賴與 import 搜尋未涵蓋所有動態路徑。
- 適用條件：樣本未觀察到某設計，不等於證明該設計在所有領域無效。

### E008

- 定位：[§16.10、Listing 3 及其後文字](https://arxiv.org/html/2609.00006v1#S16.SS10)。
- 轉述：約 90 行的範例展示模型呼叫、工具回合、訊息、限制與壓縮流程；作者明示它是示意骨架，省略 sandbox 等部署功能，對其 benchmark 表現的推測沒有證明。
- 限制：本次僅靜態閱讀，未執行或測試；不能稱為可直接部署的企業 Agent。

## Agent 摘要／推論

### 研究問題

本文回答「Agent 執行層如何組成、不同系統如何取捨」；可作系統設計的參考。使用者論文另需回答「如何衡量任務完成與回答可靠性」，不能由架構分類直接代替。[E001](#e001)–[E003](#e003)

### 方法

固定版本的原始碼比較、七面向分類及部分縱向分析；本筆記保留為作者報告，未重新檢查樣本原始碼。[E001](#e001)、[E002](#e002)

### 實驗設計

未進行本論文所需的共同任務控制實驗。表格中的歷史 benchmark 不作本研究 baseline 成績，Listing 3 也沒有本筆記已驗證的效能結果。[E003](#e003)、[E008](#e008)

### 主要發現

本文最適合供應架構分類與設計候選；作者的經驗建議、樣本觀察及未證假說須分層使用。[E001](#e001)、[E003](#e003)、[E004](#e004)、[E007](#e007)、[E008](#e008)

### 限制

- **外部效度：** coding agent 與企業問答／業務操作的資料、工具及成功條件不同。[E002](#e002)、[E004](#e004)
- **因果推論：** 架構存在、框架未被採用及複雜度觀察，都不是改善成功率的控制實驗證據。[E003](#e003)、[E007](#e007)
- **可重現性：** 本次未核讀各樣本原始碼，部分來源快照及日期呈現亦須留意。[E002](#e002)、[E003](#e003)；另見書目來源區。
- **工程完整度：** 示意骨架仍需場景工具、模型適配、部署權限與獨立測試；不應將「沒有再呼叫工具」當成「任務成功」。末項為 Agent 對評估設計的推論。[E008](#e008)

### 後續實驗候選

**Agent 建議／待確認：** 先固定企業任務、模型、資料版本、提示、步數／時間預算與重複次數；比較最小執行層、加入證據檢索、加入回答驗證等版本。每次只改明確因素，保留任務失敗與拒答，不只挑成功案例。[E003](#e003)、[E008](#e008)

- 任務完成：以預先定義、可外部檢查的結果判定；工具回傳成功及 Agent 自稱完成分開記錄。
- 回答可靠性：另外評估答案及可查核主張，區分支持、矛盾、證據不足、遺漏與拒答，並以人工核對自動評審。
- 伴隨成本：保存步數、工具錯誤／重試、延遲、token、人工介入；不能只比較一個成功率。

以上是研究設計候選。回答評估的概念來源仍需結合[第一篇 Survey E003–E008](N-20261111-001.md#e003)及其原始研究；本篇不提供已驗證的企業可靠性量表。

### 與既有文獻的關係

**Agent 綜合判斷：** 第一篇 Survey 可供回答事實性評估的分類，這篇可供執行架構的設計。這是本研究的用途分工，不表示兩篇原文互相引用或存在因果關係。
