# 隔離驗收

本目錄所有研究敘述、數字、論文與教授意見都是人造測試資料，不是實際研究證據。正式 Skill 預設必須排除此目錄。只有明確說「以驗收根目錄執行」時，才把 [fixtures](fixtures/) 當知識庫；不要把它複製到正式 notes。

## 範例與執行範圍

- 隔離根目錄：`docs/acceptance/fixtures/`。其內沿用 topics／notes／references／graphs 結構，所有資料有 test_fixture 標記。
- Skills、規範與模板仍從專案原位置讀取；根目錄切換只影響資料，不修改 Skills 設定。
- [baselines](baselines/) 保存實際變更前的來源／主題原文；不是額外來源，不能被納入 fixtures 的搜尋。
- baseline 是逐檔原文快照，內文相對連結仍以原本 fixtures 檔案位置解讀，不作獨立可導航的知識庫，也不改寫快照連結以免破壞原文比對。
- [results.md](results.md) 記錄本輪實際讀取與檔案操作；未執行的項目不能打勾。下列情境是可重複操作的檢查表，不代表全數已通過。
- 再次執行會影響的既有測試檔也先讀原文；如需重置，先展示將恢復的檔案與 baseline。不以腳本建立／清理測試資料。

## 固定資料

兩主題為 T-20261110-001（可靠性）及 T-20261110-002（評估方法，前者子主題）。五筆 N 分別為：001 Paper Alpha（摘要）、002 Meeting、003 Web（使用者摘錄）、004 Idea、005 Paper Beta（摘要）。Alpha 同屬兩主題。

C-20261110-001 是尚未驗證的「重試提高成功率」主張；Q-20261110-001 問重試成本。R-001 proposed 支持、R-002 proposed 衝突、R-003 是測試輸入預先確認的 raises_question。測試確認不代表真實使用者接受研究結論。

## 通過準則

先驗文件契約與隔離檔案行為，再於實際宿主驗證技能發現、明確／隱含觸發及工具降級。未實際執行的情境保持待驗；Mermaid 文字檢查不等於渲染驗證。全程不得建立或執行測試程式、初始化工具或批次腳本。
